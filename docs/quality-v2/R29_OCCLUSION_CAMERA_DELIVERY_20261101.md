# R29｜建筑近景遮挡感知镜头（2026-11-01）

## 动机与现象
R27 已支持照片立面朝向，工程坊 A OSM 263633887 的下半立面仍被前景建筑遮住；东一楼 263625677 的玻璃入口被树木遮挡。R27 参考截图保存在上一施工线 `docs/quality-v2/r27-entrance-workshop-online-qa/`。

## 实际做法
- 新模块 `src/building-view-occlusion.js`：纯函数 `measureBuildingViewOcclusion` 使用现有 OSM 建筑 polygon、估计建筑高度与程序化树木位置，评估相机到立面中心、下部及左右边缘共四组视线。不会移动建筑或树。
- `resolveOccludedBuildingView` 在原 `planBuildingCloseView` 之后，从有限的水平偏转、轻微抬高和近景距离候选里选择遮挡更少的机位。清晰时完全不改原视角。保留 R27 的 source-facing 照片目标及现有 Three.js 飞行动画。
- 经两轮真实截图改进，针对有照片证据的立面额外限制俯视角 `<=0.45 rad`，且不能为了躲避树木而将距离拉得比原照片近景更远。实践中工程坊 A 85.8m、东一楼 132m，俯视角均为 0.398rad。
- 只在详情面板“近看这里”触发评估；没有新增渲染器、帧循环、资源依赖、未许可照片贴图或 OSM 数据修改。

## 验收证据
- 测试采用 RED→GREEN：建筑遮挡、树冠、低层立面被挡而中心射线畅通、照片正立面俯视角约束、无遮挡保持原视角、R26/R27 兼容。
- 浏览器回归 `scripts/qa-r29-unoccluded-camera.mjs`：Edge 1440×900、触摸模拟 390×844 和 844×390，针对 263633887、263625677、263625090 分别进行建筑近景、原始详情卡片、赛车物理进入/退出。3/3 profile 通过，JS/HTTP 0 错误，机器记录及截图在 `docs/quality-v2/r29-unoccluded-camera-qa/`。
- 附加近景几何证据 `scripts/qa-r29-facade-angle.mjs`：工程坊 A 镜头距离 85.84m、东一楼 132.00m，俯视角 0.398rad；没有页面脚本错误，输出在 `docs/quality-v2/r29-facade-angle-qa/`。
- 最终 `node --test` 相关建筑、道路、赛车和近景套件 **57/57**；完整 `npm run verify` 原校园 **40/40**；`npm run build` exit 0。验证中因稀疏工作树不包含历史证据文件而报过文件缺失；补足已提交的原始资料后完整复验通过。没有以缺失证据假定功能失败。
- 两轮真实截图均经过视觉检查。工程坊 A 的主体比 R27 更完整，东一楼改善为更集中但仍含真实树木的正面构图。

## 不宣称的效果
- 工程坊 A 前景仍有建筑遮住局部、东一楼门前仍存在植被；这是地图真实空间关系与现有照片不完全匹配造成的限制。**不宣称完全无遮挡，也不宣称照片级复刻已完成。**
- 基于 OSM 多边形与示意树冠估算视线，不做 WebGL 几何/像素精确可见性计算；可能对透明叶片或装饰几何误判。
