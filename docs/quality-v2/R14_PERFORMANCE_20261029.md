# R14：植被渲染消融与 LOD 更新试验（2026-10-29）

基线为 `99eb615`，不改树木数量、位置、几何、材质、阴影、相机或分辨率。正式网站仍为 R13.1。本次研究使用独立工作树，观察到下列结果并保留原始记录。

## 单项消融：定位，不是发货设置

`r14-performance-diagnostic/results.json` 在 Edge 无界面、1440×900、DPR 1、Intel Graphics、平衡电源模式下，对全景和大道分别进行 3 轮交错测试。隐藏全部植被使全景提交三角面从 541,821 降至 174,975，帧间隔通常下降；停止 LOD 更新未见稳定的同幅度变化。暂停阴影和隐藏植被是诊断手段，均不是生产优化。数据支持继续调查植被渲染，但无法区分顶点、片元、显存带宽及其他 GPU 开销，也不能把一次快速样本当设备 FPS。

## 空间分批候选：保留实验，不纳入生产

空间分批候选将树按 300 m 网格拆为共享几何与材质的实例组，利用相机视锥裁剪；候选源码归档在 `r14-performance-production-ab/campus-vegetation-spatial-experiment.js`。分别使用生产构建、同一 Edge 进程、相同机位和连续水平平移，按 A/B、B/A、A/B 顺序采样；每次 45 帧预热、180 个新帧间隔。完整采样、环境、截图和脚本见 `r14-performance-production-ab/results.json`、`scripts/benchmark-r14-compare.mjs`。

大道同机位截图像素完全相同；全景只有 1 个像素不同。大道几何提交量降低约 21%，但全景没有裁掉几何且调用增加 66 次；帧时间高度波动，不能证明整帧加速，故不推广。该测试不是实际 iPhone、独显测试，也没有 GPU 计时或显存/占用率信息。

## 可验证的局部改进

生产实现维持原始实例分组。当相机移动后所有树木的近远 LOD 分类仍然相同时，跳过重复的实例矩阵/颜色写入和包围球重算。分类变化时正常重建；调用 `update(..., true)` 时强制重建以支持 WebGL 上下文恢复。`scripts/verify-vegetation-lod-cache.mjs` 检查不变、跨阈值及强制刷新三种情况。

`scripts/benchmark-vegetation-lod-cache.mjs` 的 2,092 棵合成树 CPU 微基准（两种操作交错、10 轮预热、各 90 次）中，不变分类 P50/P95 为 0.032/0.038 ms，强制重建为 0.383/0.524 ms，原始样本见 `r14-performance-production-ab/lod-cache-cpu.json`。这是隔离的 JavaScript 工作量，而不是整帧、GPU、线上设备的 FPS 改善；此前实景消融也显示此工作并非已确认的主要 GPU 瓶颈。

缓存候选与基线在相同 Edge、1440×900、DPR 1 下交替进行每机位三次生产构建 A/B（`r14-lod-cache-production-ab/results.json`）：全景 P95 基线 20.8 / 25.0 / 25.0 ms，候选 12.5 / 25.0 / 24.9 ms，两版均为 494 次调用、541,821 三角面；大道 P95 基线 16.7 / 29.2 / 33.3 ms，候选 25.1 / 25.0 / 25.1 ms。两组首次静态截图分别像素一致；动态镜头下不同 LOD 采样时刻导致大道计数有轻微波动。结果不足以宣称整帧稳定加速或 20% 改善。完整 `npm run verify` 和独立 `npm run build -- --outDir build-r14-cache` 通过；正式页面和真实 iPhone 未在本工作树中发布或验收。

## 未完成

需要独显/真实移动设备及较稳定条件下的生产版 A/B、WebGL GPU timer 和长期资源测量，覆盖旋转、缩放、快速飞行与更多机位；系统计时波动未解决，不宣称达到 20% P95 改善。合成基准不验证真实 iPhone Safari；空间分批也仍需动态机位、移动端、阴影和边缘裁剪回归才能考虑启用。
