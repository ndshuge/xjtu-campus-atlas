# 2026-10-25 iPhone 闪烁与场景真实性检查

## 用户反馈
在 iPhone Safari 内置网页中，西交三维校园的画面可能出现闪烁；照片显示顶部视角可以看到大量概略建筑，但并不代表所有建筑都与真实校园完全一致。

## 本轮降低移动 WebGL 内存与帧缓冲压力的修改
- 移动浏览器关闭 WebGL 多重采样抗锯齿（仍保留全场景渲染）。
- `preserveDrawingBuffer` 从 true 改为 false；浏览器不必每帧保留上一帧缓冲，降低移动 GPU 内存带宽压力。注意这可能改变截图导出行为，需单独测试。
- 移动初始像素比限制为 1，而非 1.5；桌面保持原有画质逻辑。
- 移动端使用现有纯色天空作为安全回退，不运行可能昂贵的实时大气天空 shader；PC 保持 Sky。
- 这些是针对**可能的移动端资源不稳定**所作保守性改进，不等于已定位用户手机闪烁的唯一根因。Safari 实机仍需复测。

## 地点真实性分级（当前）
- **高置信度位置**：OSM 有建筑基底或官方地图明确标注的地方；只能说明位置和轮廓有依据。
- **局部参考建模**：钱学森图书馆、主楼 E 座等，使用公开照片指导形态，未获得精确建筑 BIM/测绘成果。
- **未独立核对外观**：大多数教学楼、宿舍、道路景观设施，仍按 OSM 轮廓批量生成，不能称为真实还原。
- **实景展示**：两张已标注 CC BY-SA 4.0 的图书馆照片，可进行静态实景比较，但不能等同于完整 3D Gaussian Splatting 或 360 连续漫游。

## 下一阶段资料任务
优先逐栋整理：校园北门、主楼、中心一楼/二楼、逸夫科学馆、腾飞塔、图书馆正背立面。对每一栋建筑记录官方地图位置、多角度照片、现有 OSM 高度/层数、授予再使用许可的素材、模型差异与验收截图。没有资料时显示模型是示意，不补造假的照片级立面。

## 验收标准
静态构建与单元测试通过并不等于已在 iPhone 实机消除闪烁。需要 iPhone Safari 反复旋转/缩放、后台恢复、夜晚/白天切换、以及多次进入漫游测试，至少各 2 分钟，观察是否 GPU 画面丢失、Canvas 空白、贴图跳变。若仍闪烁，收集手机 Safari 版本和操作后复现入口，继续使用远程设备排查。
